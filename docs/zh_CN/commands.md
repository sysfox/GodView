# 命令

[← 文档首页](README.md)

只有一个命令 `/godview`（别名 `/gv`），可在控制台或游戏中使用。

输出语言遵循 [config.yml](configuration.md#locale) 中的 `locale` 设置——`zh_CN` 或 `en_US`。

## 权限

| 节点 | 默认 | 授予 |
|---|---|---|
| `godview.admin` | op | 以下所有权限 |
| `godview.link` | op | 仅 `/godview link` |

`godview.link` 的存在是为了让管理员可以不授予账号管理权限就能让版主进入面板。拥有 `godview.link` 和已有面板账号的人可以自行登录，仅此而已。

## 命令参考

### `/godview status`

服务器和插件状态一览：TPS、MSPT、堆内存、当前性能档位及原因、最近最差 tick、卡顿计数、面板地址、会话数量和存储总量。

配置变更后确认 GodView 是否在正常运行的最快方法。

### `/godview reload`

重新读取 `config.yml` 并推送到所有服务。会话保留；图表历史保留；捕获标记、告警规则、集成和地图设置立即生效。

绑定地址、端口、线程数和 TLS **不会**被重新读取——在活跃连接下重新绑定 socket 会将重载变成宕机。命令每次执行时都会告知这一点。

解析过程中的警告会在回复中计数并在控制台中完整输出。

### `/godview user add <名称> <角色>`

创建面板账号并打印生成的密码**一次**。

```
/godview user add alex operator
```

名称可使用 1–32 个字符，支持字母、数字、`_`、`.` 或 `-`。密码为 20 个字符，从去除相似字符的字母表中选取——没有 `0`/`O`，没有 `1`/`l`/`I`——因为密码需要从控制台上读取并至少手动输入一次。

回复会警告密码现在已在你的聊天日志中。这是无法避免的；登录后在面板中更改密码即可。

### `/godview user passwd <名称>>

生成新密码并**结束该账号的所有会话**。密码重置通常意味着旧密码可能已泄露。

### `/godview user role <名称> <viewer|operator|admin>`

更改角色。如果会导致最后一个启用的管理员被降级，操作将被拒绝——否则之后就没有人能管理账号了。

### `/godview user remove <名称>>

删除账号并结束其所有会话。同样拒绝操作最后一个管理员。

### `/godview user list`

列出所有账号及其角色、最近登录时间和地址。

### `/godview sessions list`

列出现有的面板会话：账号、角色、地址、空闲时间。

### `/godview sessions revoke [名称]>

结束一个账号的所有会话，或在不指定名称时结束所有会话。立即生效：GodView 在服务端维护会话信息，正是为了让"立即切断"在下一次请求时生效，而不是等到某个 token 过期。

### `/godview link`

**仅限玩家。** 为你的账号生成一次性登录链接，有效期五分钟，可在聊天中点击使用。

需要一个与你名称匹配的面板账号，或者为你的 UUID 创建的账号。

该链接是通过聊天传输的凭据——聊天内容会写入磁盘并回显到控制台。命令在打印时会给出提示，因为一个你知道已泄露的秘密远比一个你不知道已泄露的安全得多。

### `/godview unlock <IP|all>`

解除登录锁定。当你测试频率限制把自己锁在外面时使用。

## 角色

| 角色 | 权限 |
|---|---|
| `viewer` | 读取除审计日志和 INFO 级别控制台输出外的所有内容 |
| `operator` | 以上所有权限，加上踢出、封禁、传送、游戏模式、广播、世界天气和时间、控制台命令 |
| `admin` | 所有权限，包括面板账号管理、会话撤销、配置重载和告警测试 |

选择三种角色而非权限矩阵：服务器的运维团队规模很小，而一个没人能理解的矩阵比所有人都能理解的粗略划分更糟糕。真正重要的区分在于读取、对玩家采取行动，以及决定谁可以登录。

有两件事故意设置得比你预期的更严格：

- **审计日志需要 `admin` 权限。** 它记录了谁做了什么，包括失败的尝试。
- **INFO 级别的控制台输出需要 `operator` 权限。** 警告和错误是 viewer 需要关注的内容，但 INFO 输出通常会包含玩家加入时的 IP 地址。

API 中的玩家地址遵循同样的规则——`GET /api/players` 仅对能够对玩家执行操作的角色包含地址信息。

## 所有操作都会被审计

在游戏中进行的账号变更与面板操作出现在同一个审计日志中，地址显示为 `in-game`。因此控制台的 `/godview user add` 和面板的封禁操作都在同一个历史记录中。
