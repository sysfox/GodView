# 地图

[← 文档首页](README.md)

世界的俯视图，基于实时区块数据绘制。

## 开销

这是需要首先理解的内容，因为它是 GodView 中唯一你可能需要调整预算的部分。

渲染一张瓦片需要区块数据，而获取 `ChunkSnapshot` **必须**在主线程上进行。之后的所有工作——遍历列、着色、PNG 编码——都是对分离副本的纯计算，在独立的线程上运行。

因此主线程只做最小的工作：最多 `map.chunks-per-tick` 个快照，然后交给其他线程处理。

```yaml
map:
  chunks-per-tick: 4
```

在默认值 4 的情况下，一个完整的 8×8 瓦片需要 16 个 tick——不到一秒——而每个 tick 的开销远低于一毫秒。**在低端服务器上将此值设为 1 或 2。** 一个按需渲染整个区域的地图插件正是 GodView 自身的卡顿检测器存在的理由。

预算也会随[性能档位](configuration.md#profile)缩放：`full` 档下翻倍，`low` 档下减半。开启 `idle-suspend` 后，没有人打开面板时不会捕获任何瓦片。

## 瓦片

```yaml
map:
  chunks-per-tile: 8      # 8 x 8 区块 = 128 x 128 像素
  tile-cache-mb: 24
  tile-ttl-seconds: 300
```

每像素对应一个方块列。`chunks-per-tile` 必须是 1 到 32 之间的 2 的幂，因为瓦片坐标是通过位移区块坐标得出的。

请求中的 `scale` 参数用于缩小显示：`2` 表示四分之一像素，`4` 表示十六分之一。面板会随着缩放自动切换。

**每次捕获生成所有缩放级别。** 当一个区域被快照后，缩放级别 1、2 和 4 都会从同一份区块数据渲染并一起缓存。列遍历随缩放的平方减少，因此额外两个级别只花费第一个级别的约三分之一——放大缩小从此不再需要额外开销。在 1.1.0 之前，捕获队列以缩放级别为键，这意味着缩小会以十六倍的瓦片数量再次请求同一块地面，预算永远无法完成。

内存缓存以**字节**而非瓦片数量为界。一片海洋瓦片压缩后只有几千字节，一个丛林村庄约五十千字节，因此"保留 200 个瓦片"可能意味着半兆字节到十兆字节不等——而 `tile-cache-mb` 就成了一个毫无意义的数字。驱逐策略为最近最少使用，这很适合地图的实际浏览方式。

瓦片也会在 `tile-ttl-seconds` 后过期，因为世界会变化。一张显示一小时前被拆除的基地的地图比空白地图更糟糕。

## 存储的瓦片

```yaml
map:
  persist: true
  persist-days: 7
```

已渲染的瓦片写入 `plugins/GodView/map/`，每个世界一个目录，每个瓦片和缩放级别一个文件。

这就是让地图不断积累而非重置的原因。仅靠内存，比 `tile-ttl-seconds` 更旧的瓦片必须以 `chunks-per-tick` 速度重新捕获，地图永远无法显示该预算在一个 TTL 内所能产生的更多世界——只能显示玩家碰巧站立的周围小范围。有了存储，一个区域被捕获一次后就会保留：平移查看别人已经看过的地面只消耗一次文件读取，而不是 64 个区块快照。

**只有完整的瓦片才会被存储。** 在某些区块未加载时渲染的瓦片会有空洞，持久化这些空洞会让它们变成永久的。这些瓦片以二十秒的生命周期保留在内存中，等待区块到达后重新绘制；响应中携带 `X-GodView-Complete: false` 标记，面板据此知道需要再次请求。

早于 `persist-days` 的文件在读取时会被删除，并在启动时在后台线程中清理。设置 `persist: false` 可以将所有内容保留在内存中，代价是地图永远不会超出 tick 预算的限制。

## 未加载的区块

```yaml
map:
  load-unloaded: true
  unloaded-per-second: 8
```

**自 1.1.0 起默认开启。** 关闭时，地图只能绘制当前恰好加载的区块——每个玩家周围几十个——其他所有区域渲染为虚空。这不是细微的差别：这是地图和模糊色块之间的区别。

未加载的区块以**异步**方式请求，速率限制为 `unloaded-per-second`。无需等待结果：区块在下次渲染该瓦片时可用，因此在几秒后填充，而不是花费一个 tick 阻塞在磁盘读取上。

如果服务器的磁盘是瓶颈，可以关闭此功能。地图将仅显示在面板打开时有人活动过的区域——开启 `persist` 后，这仍然会不断积累。

## 方块的绘制方式

对每个方块列，从最高方块向下遍历直到找到不透明方块，着色，然后根据其北邻方块进行明暗处理，使地形具有立体感。使用三个明暗级别而非平滑渐变，与 Minecraft 自身地图的处理方式一致——在小尺寸下更清晰。

水单独处理：下方的地板被着色后按深度染色，这使得海岸线和落差可辨认，而非一片平坦的蓝色。海带和海草不会阻止向下遍历，否则海带森林会渲染成不透明的绿色板块。

### 颜色

方块颜色按**名称**匹配，而非枚举 `Material` 枚举。

Minecraft 每次更新都会增加数十种方块。完全基于枚举构建的颜色表会将每种新木材、石材变体和铜块状态渲染为空白灰色，直到有人更新插件。按名称匹配意味着名为 `PALE_OAK_PLANKS` 的方块在上线当天就会以木板颜色绘制，而 GodView 无需知道它的存在。

命名的方块获得精确颜色；其他所有方块按从最具体到最一般的规则依次匹配——任何以 `_LEAVES` 结尾的是树叶，`DEEPSLATE*` 在通用石材规则认领之前先被认领为深板岩，`_STAIRS` 根据前缀解析为木材或石材。

## 请求瓦片

```
GET /api/map/tile/{world}/{tileX}/{tileZ}?scale=1
```

仍在渲染中的瓦片返回 **202** 而非阻塞：

```json
{ "status": "rendering", "capturedChunks": 24, "totalChunks": 64 }
```

并附带 `Retry-After: 1`。请再次请求。这保证了全屏平移——同时请求数十个瓦片——不会在捕获队列逐 tick 排空时阻塞所有的 HTTP 工作线程。

已就绪的瓦片带有 ETag 和一分钟的浏览器缓存过期时间，因此滚动回已经看过的区域只消耗一次 304 而非重新渲染。它们还携带 `X-GodView-Complete`；`false` 表示某些区块缺失，浏览器缓存过期时间降至五秒，值得稍后再次请求。

面板从中间往外的顺序请求瓦片，每次几个，并使用退避重试。所有结果都是可重试的——这就是关键。在 1.1.0 之前，返回 200 或 202 以外的任何状态的瓦片会被缓存为永久空白，永远不会再次请求，因此地图填满一片区域后就停止了。

## 关闭地图

```yaml
map:
  enabled: false
```

或按世界关闭：

```yaml
map:
  disabled-worlds:
    - "world_nether"
    - "creative_plots"
```

对已禁用世界的请求返回 404 并附带说明消息，面板会将其从世界选择器中隐藏。

## 这不是什么

这是一个实时的运维视图——玩家在哪里、实体热点在哪里、地形现在看起来如何。它不是一个公开的地图：没有预先渲染的无人查看的地形存档，没有超过缩放 4 的瓦片金字塔，没有匿名访问。覆盖范围随着面板的使用而增长，而非作为后台任务。

如果你需要公开地图，请同时运行 Dynmap 或 BlueMap。它们解决的是不同的问题，而且解决得很好。
